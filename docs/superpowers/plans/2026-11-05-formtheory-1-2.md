# FormTheory 1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make FormTheory operable at scale and release-ready: entries management, form duplicate/import/export, clean uninstall, privacy tooling, webhook delivery log with retry, full i18n, wordpress.org readiness, CI.

**Architecture:** Extend `FormTheory_DB` (entry status/notes/search/bulk, webhook log table, purge). Add three focused classes: `FormTheory_Portable` (form JSON import/export), `FormTheory_Privacy` (retention cron, WP exporter/eraser), and extend `FormTheory_Webhooks` to deliver via a log row. Admin gets `assets/admin.js` (confirm dialogs, select-all) replacing inline `onclick`. Payments are out of scope.

**Tech Stack:** PHP 7.4+, WordPress 6.0+, vanilla JS, PHPUnit 9 + Brain Monkey (dev only), WP-CLI `i18n make-pot` (dev only), GitHub Actions.

**Spec:** Conversation answer "1.2 candidates" + "Release hygiene" (user: "All (except payments)"). Plan 1.3 (`2026-11-05-formtheory-1-3.md`) covers the feature list.

## Global Constraints

- PHP 7.4 syntax floor (no enums, no `match`, no readonly props, no arrow-fn-only features beyond 7.4).
- No front-end build step; no runtime Composer deps.
- Text domain `formtheory`; hooks/options/tables prefixed `formtheory_`.
- Every admin write action: `current_user_can( 'manage_options' )` + nonce via `FormTheory_Admin::guard()`.
- All SQL through `$wpdb->prepare`; `LIKE` terms through `$wpdb->esc_like`.
- Schema changes via `dbDelta` in `FormTheory_DB::install()`; bump `FORMTHEORY_VERSION` to `1.2.0` (triggers auto-upgrade). Existing 1.1 entries get `status = 'read'`.
- WCAG 2.2 AA: no inline `onclick`; bulk checkboxes labelled; targets ≥24px; focus visible.
- Uninstall deletes data only when the opt-in setting `delete_on_uninstall` is on (default off).

## Review Focus

- Search term `100%_ "x"'; DROP` → matches literally, no SQL error, no wildcard expansion.
- Bulk action posted with empty list, non-numeric ids, or ids belonging to another form → no-op or scoped to the form; never touches other forms' entries.
- Import of malformed JSON, wrong marker, 5 MB file, `<script>` in html field, webhook secrets → error or sanitized; secrets never exported.
- Retention days `0` or blank → nothing purged (never "purge everything").
- Webhook endpoint permanently down → exactly 3 attempts then `failed`; no endless cron.
- Privacy eraser for an email matching no entries → `done`, nothing removed; matching entry with a file → file deleted too.

### Task 6: Webhook delivery log and retry

**Files:**
- Modify: `includes/class-webhooks.php`, `includes/class-db.php` (table + helpers), `includes/class-admin.php` (Webhook Log submenu + retry handler), `tests/WebhooksTest.php`
- Create: `tests/WebhookRetryTest.php`

**Interfaces:**
- Table `{prefix}formtheory_webhook_log`: `id`, `form_id`, `entry_id`, `url` varchar(2048), `request` longtext (JSON `{body,headers}`), `status` varchar(10) (`pending|ok|failed`), `http_code` smallint, `attempts` tinyint, `error` varchar(255), `created_at`, `updated_at`; `KEY form_id`, `KEY status`.
- `FormTheory_DB::log_webhook( int $form_id, int $entry_id, string $url, array $request ): int`; `update_webhook_log( int $id, array $fields ): void`; `get_webhook_log( int $id ): ?array`; `list_webhook_log( int $limit, int $offset, string $status = '' ): array`.
- New cron hook `formtheory_deliver_webhook( int $log_id )`. `dispatch()` now creates a log row then schedules this hook. Legacy `formtheory_send_webhook( $url, $request )` stays registered unchanged for events queued by 1.1.
- `FormTheory_Webhooks::deliver( int $log_id ): void` — sends via `wp_safe_remote_post` (5 s). Success = 2xx → `ok`. Otherwise `attempts++`; if `attempts < 3` schedule `wp_schedule_single_event( time() + 60 * 4 ** attempts, … )` and keep `pending`; else `failed`. Records `http_code` / sanitized error text.
- `FormTheory_Webhooks::next_delay( int $attempts ): int` → `60 * 4 ** $attempts` (60, 240, 960).
- Admin: **FormTheory → Webhook Log** table (time, form, URL host only, status, code, attempts) with Retry (nonce `formtheory_webhook_retry`, resets `attempts=0`, status `pending`, reschedules). Log rows older than retention purge with entries (Task 5 job).
