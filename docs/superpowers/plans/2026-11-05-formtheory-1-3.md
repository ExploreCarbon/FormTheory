# FormTheory 1.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add calculated fields, rating, address, signature and repeater fields, save-and-resume for long forms, and a real block-editor experience. Payments are out of scope.

**Architecture:** One seam first: `FormTheory_Fields::value_to_text()` so composite values (address, repeater, signature) render identically in admin, CSV, merge tags and webhooks. Each new field type is one sanitize branch in `FormTheory_Fields`, one render branch in `FormTheory_Frontend::render_field`, one builder panel in `assets/builder.js`. Calculations use a hand-written tokenizer/shunting-yard evaluator (`FormTheory_Calc`) mirrored in JS; the server result always wins. Drafts live in a new hashed-token table.

**Tech Stack:** PHP 7.4+, WordPress 6.0+, vanilla JS, `wp.element`/`wp.blocks` globals for the block (no build step), PHPUnit 9 + Brain Monkey.

**Spec:** Conversation answer "1.3 candidates" (user: "All (except payments)"). Depends on plan 1.2 (`2026-11-05-formtheory-1-2.md`) being merged: uses `purge` cron, i18n conventions, `FORMTHEORY_VERSION` 1.2.0.

## Global Constraints

- PHP 7.4 syntax floor; no front-end build step; no runtime Composer deps.
- Text domain `formtheory`; hooks/options/tables prefixed `formtheory_`; all strings translatable (1.2 convention).
- Never `eval()`. Never trust client-computed values: calc, signature and repeater are validated/recomputed server-side.
- All new config keys sanitized in `FormTheory_Fields::sanitize_config`.
- WCAG 2.2 AA: every new control keyboard-operable, labelled, ≥24px target; signature has a typed alternative (2.5.7); errors via existing `aria-live` flow.
- Bump `FORMTHEORY_VERSION` to `1.3.0`. 1.2 configs and entries load unchanged.

## Review Focus

- Calc formula dividing by zero, referencing a missing/hidden/non-numeric field, or containing `;`, `$`, function-call text → result empty or `0`, no PHP error, no code execution.
- Signature payload that is oversize, not a PNG (SVG, HTML, polyglot), or malformed base64 → field error, nothing written to disk.
- Resume link with unknown, expired or truncated token → same generic "link expired" message (no enumeration); email-me-link spam → rate-limited.
- Repeater posted with more rows than `max_rows`, all-empty rows, or a row key not in the configured columns → extra rows rejected, empty rows dropped, unknown keys ignored.
- Rating/address values outside range or with missing required parts → field-level error, partial address with `required` fails.

### Task 2: Calculated field

**Files:**
- Create: `includes/class-calc.php`, `tests/CalcTest.php`
- Modify: `includes/class-fields.php` (type `calc`), `includes/class-frontend.php` (render readonly output, recompute in `process`), `assets/front.js` (JS mirror), `assets/builder.js`, `formtheory.php`

**Interfaces:**
- Produces:
  - `FormTheory_Calc::evaluate( string $formula, array $values ): ?float` — grammar: numbers, `{field:ID}`, `+ - * /`, parentheses, unary minus. Field values coerced: numeric string → float, otherwise `0`. Division by zero or syntax error → `null`.
  - `FormTheory_Calc::is_valid( string $formula ): bool` — same grammar, ids of form `[a-z0-9_]+`; used at save time (invalid → field's `formula` saved as `''`).
  - Field config: `formula` (string), `decimals` (int 0–6, default 2), `prefix` / `suffix` (short text).
  - `calc` is a data field (stored), never required, excluded from `cond` sources only if its formula is empty.
- Server: in `process()`, after sanitizing posted values, each visible `calc` value is **overwritten** with `round( evaluate(...), decimals )` (as string) or `''` for `null`. Posted value for a calc field is ignored.
- JS: `evaluateFormula( formula, getValue )` produces the same results for the test vectors below; updates the `<output>` on `input`/`change`.

**Interfaces:**
- Type `signature`. Two inputs, either satisfies `required`: hidden `ft[ID][data]` (canvas `toDataURL('image/png')`) and text `ft[ID][typed]` ("Or type your full name"; max 120 chars).

- Stored value: `['sig'=>file,'name'=>…]` or, for typed-only, `['typed'=>'Ann Lee']`; `value_to_text` (Task 1) renders both (`[signature] Ann Lee` / `Ann Lee (typed)`).

### Task 6: Repeater field

**Files:** `includes/class-fields.php`, `includes/class-frontend.php`, `assets/front.js`, `assets/builder.js`; Test: `tests/RepeaterTest.php`.

**Interfaces:**
- Type `repeater`; config `columns`: list (1–6) of `{id, label, type ∈ text|email|number|phone|date|textarea|select, options[]}` (ids unique within the field), `min_rows` (0–20, default 1), `max_rows` (1–20, default 5, ≥ min), `add_label`.
- Posted `ft[ID][ROW][COL]`. `FormTheory_Frontend::sanitize_repeater( array $f, $raw ): array` returns list of rows (reindexed) keyed only by configured column ids, each cell sanitized by the column type's rules; fully empty rows dropped; rows beyond `max_rows` dropped (and validation error `Too many rows.` emitted by `validate`).
- Validation: `required` = at least `min_rows` (≥1) non-empty rows; per-cell type validation reuses `validate()`; error keyed to the repeater field.
- Front JS: "Add row"/"Remove row" buttons (≥24px), new rows get fresh indexed names, focus moves to first control of the added row, an `aria-live` region announces "Row added/removed".
- Not a conditional-logic source.

### Task 7: Save and resume

**Files:**
- Create: `includes/class-drafts.php`, `tests/DraftsTest.php`
- Modify: `includes/class-db.php` (table), `includes/class-frontend.php` (shortcode: resume + button; AJAX `formtheory_save_draft`), `includes/class-fields.php` (form key `save_resume`), `includes/class-privacy.php` (purge), `assets/front.js`, `assets/builder.js`

**Interfaces:**
- Table `{prefix}formtheory_drafts`: `id`, `form_id`, `token_hash char(64)` (unique), `data longtext`, `page tinyint`, `created_at`, `expires_at`.
- `FormTheory_Drafts::create( int $form_id, array $values, int $page ): string` → raw token (`wp_generate_password( 32, false )`); only `sha256( token )` stored; expiry 30 days (filter `formtheory_draft_ttl`). File and signature values are **not** saved.
- `FormTheory_Drafts::load( int $form_id, string $token ): ?array` → `['values'=>…,'page'=>int]` or `null` for unknown/expired/wrong-form; compare with `hash_equals`.
- `FormTheory_Drafts::delete( string $token )`; `purge_expired(): int` called from the daily `formtheory_purge` job (1.2).
- AJAX returns `{ok, url}` where `url` = current page + `?ft_resume=TOKEN`; optional posted `email` (validated with `is_email`) sends the link via `wp_mail`; limit 5 emails/hour/IP via transient `formtheory_draft_rl_<md5(ip)>`.
- Form config `save_resume` bool (default false). Successful submit with a `ft_resume` token deletes the draft.
- Nonce `formtheory_submit_<form_id>` required on save (same as submit).
